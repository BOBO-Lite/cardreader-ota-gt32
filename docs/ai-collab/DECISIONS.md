# DECISIONS.md — 长期架构决定

> 仅记录跨任务仍有效的决定（ADR 风格，短）。日常切片细节见任务卡与交付卡。  
> 行为细则仍以 [`../YMODEM-GT32-D1-R02.md`](../YMODEM-GT32-D1-R02.md) 为权威。

---

## ADR-001 — 仅新板；旧板不在范围

- **日期**：2026-09-11  
- **决定**：本轮只做有 GT32L32S0140 的新板 BootLoader OTA；无外挂旧板不做、不混发。  
- **理由**：分区与介质模型与旧板不兼容；双轨会放大 Meta/BKP 风险。  
- **后果**：文档与代码不保留旧板 Backup 片内路径；旧 App 与新 Boot 的 BKP2 规则不得混用发布。

---

## ADR-002 — 保留 R10 YMODEM-in-Boot；Backup 映射为 GT32 Secondary

- **日期**：2026-09-11  
- **决定**：OTA 阶段仍在 Boot 内跑 YMODEM（DMA 单缓冲等行为骨架沿用 R10）；原片内 Backup 改为 GT32 用户区 Secondary（128 KiB @ `0x00000`）。  
- **理由**：协议状态机已在旧稿跑通；新板 16 KiB Boot 更宽裕；片内空间让给 App 110 KiB。  
- **后果**：预擦/写入走 `gt32_raw`；禁止 Chip Erase；擦除时长需实板登记（默认发送端等 C 30 s）。

## ADR-003 — Meta 在片内；LastGood 在 GT32；v1 不做 BKP2 耗尽自动恢复

- **日期**：2026-09-11  
- **决定**：三旗标与镜像信息仅片内 Meta（基址 `0x0801F800`，事务只擦 1 KiB 页）；LastGood 在 GT32 `0x20000`（128 KiB），安装前强制备份成功才允许擦 App；BKP2≥5 时 **v1 策略 B：只进 OTA**，不自动 LastGood→App。  
- **理由**：上电选路不依赖外挂；避免 SPI 故障导致误判；自动回滚留二期以降复杂度。  
- **后果**：AC-YM-21 不测自动恢复；v1 无外挂 OTA meta。

## ADR-004 — `board_id=0x0001`；Meta CRC 间断覆盖

- **日期**：2026-09-11  
- **决定**：Meta 有效头扩至 88 字节，在原保留区插入 `board_id`（小端 uint32，固定 `0x0001`）；Meta CRC 覆盖 `0x00～0x43` **与** `0x54～0x57`（共 72 字节），不含三旗标与 CRC 自身；向引擎按**升序地址**依次喂入。  
- **理由**：误刷防护；与旧 84 字节布局字段偏移兼容地扩展；间断字段顺序钉死避免实现分歧。  
- **后果**：编解码必须按升序拼接再算 CRC；出厂包与 Boot 提交共用同一算法（poly `0xEDB88320`）。

## ADR-005 — AppOta C API（BKP）；Modbus FC 不在范围；OTA 阶段用 YMODEM

- **日期**：2026-09-11（R02.1）  
- **决定**：App↔Boot 契约为小 C API：`AppOta_RequestUpgrade()` / `AppOta_ConfirmRunning()`（写 BKP1/BKP2 + 复位/确认）。**不做** Modbus 功能码/寄存器映射；主机协议日后 ACK 后调用 API 即可。进入 Boot 后总线交给 YMODEM。  
- **理由**：解耦业务协议与 Boot 契约；避免在设计包中钉死未定的 Modbus 映射。  
- **后果**：Slice 8 仅交付 AppOta；最终 ACK ≠ 升级成功；成功以 App 业务应答+版本+ConfirmRunning 为准。

## ADR-006 — 个人+AI 采用 EAI-DP，不强制团队 R 门禁

- **日期**：2026-09-11  
- **决定**：协作按 EAI-DP V1.2 执行 A0–A3 与 E0–E4；**不强制**共享治理 R0–R2 团队评审门禁。A3 仍要求设计冻结、独立 AI 复审、人对关键路径与证据审查；板端擦写需显式用户授权。  
- **理由**：个人+AI 场景无固定评审角色；弱化官僚的同时保留嵌入式红线与证据强度。  
- **后果**：文档集以本目录最小集为准；不得用「无 R 门禁」跳过 A3/E4。

## ADR-007 — LastGood「当前 App 有效」= 向量 OK（不要求 Meta APP_VALID）

- **日期**：2026-09-11（R02.1）  
- **决定**：安装前若 MSP 在 RAM 且 8 字节对齐 **且** Reset 带 Thumb 位并落在 App 链接范围 → 必须成功整槽拷贝 112640 字节到 LastGood，失败则安装失败、不擦 App；向量 NOT OK → 跳过 LastGood 继续安装。**不**以 Meta `APP_VALID` 为前置（READY 提交会清 VALID）。  
- **理由**：READY 提交后 VALID 已清，用 VALID 会永远跳过备份；向量是唯一可信“当前 App 可保”信号。  
- **后果**：AC-YM-21 覆盖向量 OK/NOT OK 两分支；跳过时无回滚可用。

## ADR-008 — Boot 栈 ≥ 0x800；DMA RX static 2048；ISR 仅冻结标志

- **日期**：2026-09-11（R02.1）  
- **决定**：Boot 主栈 ≥ `0x800`（2048）；DMA 接收缓冲为 **static 2048**（禁止大栈 VLA）；IDLE/DMA ISR 内禁止 Flash 擦写/编程、YMODEM 解析、GT32 操作——仅冻结轮次标志。  
- **理由**：防止栈溢出与 ISR 长路径破坏时序/看门狗；与 R10 单缓冲模型一致。  
- **后果**：链接/启动文件须显式满足栈预算；协议与介质操作只在主循环/`boot.c`。

---

## ADR-009 — GT32 MCU 侧 WIP 超时钉死

- **日期**：2026-09-11（R02.1）  
- **决定**：Page Program WIP 超时 **100 ms**；Sector Erase 4KB **500 ms**；Block Erase 64KB **2000 ms**。Secondary 整槽预擦墙钟须兼容发送端等 C 默认 30 s；实板记入 AC-YM-05，超限则设计变更上调发送端等待，不得静默改协议。  
- **理由**：避免无限轮询；与发送端等待解耦——擦除墙钟与协议字节时序分治。  
- **后果**：`gt32_raw` 必须实现超时错误码并归入传输/安装失败出口。

## ADR-010 — 移植 R10/v0.3.1 `boot.c`，非协议绿场重写

- **日期**：2026-09-11（R02.1）  
- **决定**：实现优先移植 `CardReaderBootLoader-v0.3.1` / R10 `boot.c` 状态机到 GT32 布局与 `gt32_raw`，而非从零重写 YMODEM 协议。仓库路径 **待工程确认**。  
- **理由**：协议状态机已在旧稿验证；降低回归面。  
- **后果**：Slice 4 以移植+适配为主；路径未确认前不得编造 Keil/仓库绝对路径。

## ADR-011 — 板卡从 v0.1 起；手册截至 2026-09-11

- **日期**：2026-09-11（R02.1）  
- **决定**：板卡版本从 **v0.1** 起计；GT32 手册引用 **VER1.0I_N**；GD32F103 用户手册写「截至 2026-09-11 最新版」，不编造假修订号。  
- **理由**：与用户钉死的基线一致；避免文档假修订号误导实现。  
- **后果**：冻结卡/AGENTS 同步该表述；SPI 引脚仍待原理图，不得 invent。
