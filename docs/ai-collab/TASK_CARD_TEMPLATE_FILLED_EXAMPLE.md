本次不做：
YMODEM；gt32_raw；Meta 整页擦写事务；安装；App Modbus；出厂工具完整实现
（工具可后续复用本片 codec，但不在本片范围展开）。

完成标准：
- AC-S1-1：ota_layout.h 常数与 R02 §2.1 一致（Boot/App/Meta/Secondary/LastGood/APP_IMAGE_MAX）

- AC-S1-3：Meta CRC32 覆盖 0x00～0x43 + 0x54～0x57；算法与样例 ASCII「123456789」→ 0xCBF43926 一致
- AC-S1-4：大小字段解析拒绝 <8 或 >112640；文件名规则可主机测（超长/非 cardreader 前缀）
- AC-S1-5：目标构建或主机测试目标通过（E1/E2）；无实机 Flash 擦写

主机单元测试 / 固定向量对比；目标编译进 Boot 或测试桩（E1）；不要求本片 E3。

### A3 设计冻结引用 + 本片方案摘要

```text
方案标识/版本：YMODEM-GT32-D1-R02 + DESIGN_FREEZE；本片 = IMPLEMENTATION_PLAN Slice 1
本次行为变化：
  新增/落地分区常数头文件与 Meta 编解码实现及主机可重复验证向量。

  R02 分区与 Meta 布局；不引入 YMODEM/SPI；不擦写 Flash。
本次不做：
  见第 1 节。

接口、状态和数据所有权：
  codec 提供序列化/反序列化与 CRC 计算 API；调用方拥有 RAM 中的镜像信息结构；
  本片不拥有 Flash 事务。
正常路径：
  RAM 结构 → 按偏移写入 88 字节缓冲区 → 计算 Meta CRC → 填入 0x44；
  反向：缓冲区 → 解析字段 → 校验 CRC（可选 API）→ 得到结构。
错误、超时、复位和掉电路径：
  解析错误返回失败；本片无超时/掉电路径（无 Flash 写）。
兼容性要求：
  与 R02 §3.4 及出厂包字段一致；供后续 Slice 5/9 复用。
资源和时序预算：
  无新增协议时序；代码体积计入 Boot ≤16 KiB 总预算（本片增量在交付卡报告）。

预计修改文件：
  ota_layout.h；ota_meta_codec.c/.h；主机测试文件（路径待工程确认）
任务切片及依赖：
  无前置切片；为 Slice 5/9 前置
允许连续实施的切片与汇报检查点：
  默认仅 Slice 1；完成后停止并交交付卡

AI 建议但不实施的额外逻辑：
  - 在 codec 内自动写 Flash（拒绝，属 Slice 5）
  - 从文件名解析 board_id（拒绝，R02 规定 Boot 写常量）

  任何与 R02 偏移/CRC/board_id 不一致的“优化”；新增计划外持久化格式。
```
